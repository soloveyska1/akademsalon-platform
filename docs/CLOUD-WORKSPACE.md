# Работа над Салоном из браузера

Откройте [Codex Cloud](https://chatgpt.com/codex/cloud) под тем же аккаунтом ChatGPT.
Выберите окружение **«Академический Салон — основной проект»**, репозиторий
`soloveyska1/akademsalon-platform` и ветку `main`. Напишите задачу обычными словами.
Задача выполняется в облаке; Mac можно выключить. С другого устройства откройте
эту же облачную задачу, чтобы продолжить её контекст.

[Прямая ссылка на настроенное окружение](https://chatgpt.com/codex/cloud/settings/environment/6ac059e9e520819188deb814e4040a5e).
Окружение сохранено и проверено 3 октября 2026 года: холодная подготовка,
повторная подготовка из кэша и полный `check.sh` завершились успешно в облаке.

Изменения завершённой задачи нужно сохранить в GitHub через проверенный commit/PR.
Новая задача получает свою рабочую копию; незакоммиченные изменения другого
компьютера и локальные чаты не синхронизируются через Git. Для продолжения на Mac
сначала проверьте dirty state и получите нужную ветку из GitHub.

## Воспроизводимая подготовка

Образ Codex `universal`, Node.js **22**, Python **3.12**; Git предустановлен.
Переменная окружения `PYTHONDONTWRITEBYTECODE=1` предотвращает появление
неотслеживаемого Python-кэша при проверках в новой рабочей копии.
Скрипт установки выполняет подготовку и проверки:

```sh
set -eu
bash scripts/cloud-workspace/setup.sh
bash scripts/cloud-workspace/check.sh > /tmp/salon-check.log 2>&1
tail -n 14 /tmp/salon-check.log
test -z "$(git status --porcelain)"
printf "CLOUD_CHECKS_PASSED CLEAN_CHECKOUT_VERIFIED\n"
```

Скрипт обслуживания восстанавливает и проверяет baseline при каждом запуске:

```sh
bash scripts/cloud-workspace/setup.sh
```

Сеть агента ограничена `github.com`, `api.github.com`,
`raw.githubusercontent.com` и `codeload.github.com`; HTTP-методы разрешены для
Git fetch/push. На этапе установки Codex отдельно предоставляет сеть для
получения проверяемого публичного baseline. Секреты среды не требуются.

Установка использует только Git, Node.js и стандартную библиотеку Python,
не требует локальных путей, SSH, API-ключей или платных сторонних сервисов.
Подготовка получает опубликованные статические файлы GET-запросами с
`https://akademsalon.ru`, проверяя каждый SHA-256 по сохранённому release manifest.
При несовпадении она останавливается: новый релиз нужно отдельно сверить и
обновить в `scripts/cloud-workspace/prepare.py`.

После подготовки:

```sh
bash scripts/cloud-workspace/check.sh
python3 scripts/cloud-workspace/serve.py
```

Превью работает на `http://127.0.0.1:8000`; в облачной задаче агент открывает его
доступным инструментом браузера и предоставляет результат проверки. Сервер
останавливается через Ctrl+C. Если среда предоставляет браузерное перенаправление
порта, сохраняйте его закрытым для посторонних.

## Какую версию редактировать

Перед каждой задачей прочитайте `AGENTS.md`, `docs/brain/START-HERE.md` и
`docs/brain/CURRENT-HANDOFF.md`. Именно handoff определяет актуальный релиз;
даты и указатели в старых разделах README/START-HERE могут быть историческими.

Корневые HTML и `npm run build` сейчас не воспроизводят последние production
overlays. Не публикуйте их поверх работающего сайта как «свежую версию».
Настройка создаёт отдельную опорную копию **release228-intake-da171f06**:

- `tmp/cloud-workspace/baseline/` — 534 файла с проверенными хешами;
- `/expertise.html` — серверный 301 на `/`, а не 535-й доступный файл;
- `tmp/cloud-workspace/public/` — рабочее превью; повторная настройка сохраняет
  сделанные здесь правки;
- `tmp/cloud-workspace/baseline.json` — результат проверки и исходный manifest.

`tmp/` игнорируется Git. Любую принятую правку превью оформляйте в отслеживаемых
исходниках/релизном скрипте и evidence текущего workstream, затем воспроизводите
её из baseline. Одних изменений в `tmp/` недостаточно для сохранения в GitHub.

API в превью возвращает `503` и `ok:false`. Превью не подключено к рабочей базе,
боту, авторизации, оплатам и отправке заявок. CSP блокирует внешние fetch/form
запросы. Backend и выпуск в production — отдельная задача с отдельным доступом.

При браузерном тестировании существующих релизов используйте их изолированные
сценарии и задавайте `SALON_NODE_DEPS` на каталог с Playwright этой среды, а не
на путь с Mac. Некоторые исторические проверки требуют `channel: 'chrome'`;
наличие Chromium само по себе не подтверждает наличие Google Chrome.

## Контекст между устройствами

Долговечные решения находятся в `docs/brain/`, итог работы — в handoff своего
workstream. Соблюдайте свежий `git fetch origin`, объявления scope и проверки
конфликтов из `AGENTS.md`. Наличие облака не даёт знания о чужих unpushed/dirty
изменениях. Секреты и клиентские материалы не сохраняйте в репозитории.

Официальные инструкции: [облачные окружения Codex](https://learn.chatgpt.com/docs/environments/cloud-environments)
и [настройка используемого веб-интерфейса](https://learn.chatgpt.com/docs/environments/cloud-environment).

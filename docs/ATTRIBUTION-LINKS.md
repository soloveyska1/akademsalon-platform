# Разметка каналов и подача адресов в поиск

Два узких места из среза `analysis/growth-baseline-2026-07-24.ipynb`: 80,9%
сессий попадают в `direct_or_unknown`, а из поиска приходит 5,7%. Ниже — что
сделано в коде и что нужно сделать руками, чтобы это сдвинулось.

## 1. Метка канала `?s=`

Telegram и VK открывают ссылки во встроенном браузере и срезают `Referer`.
Переход из бота приходит без источника и неотличим от прямого захода — отсюда
и берётся большая часть тех 80,9%. Полный набор `utm_*` в сообщение бота руками
не вставишь, поэтому добавлена короткая метка.

Готовые ссылки — копировать как есть:

| Куда ставить | Ссылка | Как ляжет в отчёт |
|---|---|---|
| Сообщения бота | `https://akademsalon.ru/?s=tg` | `telegram` / `bot` |
| Посты в Telegram-канале | `https://akademsalon.ru/?s=tgch` | `telegram` / `channel` |
| VK — посты и группа | `https://akademsalon.ru/?s=vk` | `vk` / `social` |
| Реферальные ссылки | `https://akademsalon.ru/?s=ref` | `referral` / `word_of_mouth` |
| QR-коды, офлайн | `https://akademsalon.ru/?s=qr` | `qr` / `offline` |
| Ссылки в Atom-ленте | `https://akademsalon.ru/?s=feed` | `feed` / `rss` |

Метка работает на любой странице, не только на главной:
`https://akademsalon.ru/guide-normocontrol.html?s=tgch`.

Правила, которые стоит знать:

- **Список закрытый.** `?s=` со значением не из таблицы игнорируется целиком —
  посторонний не может сочинить себе источник через ссылку.
- **Явные `utm_*` главнее.** В ссылке `?s=tg&utm_source=yandex` источником
  останется `yandex`, а метка только дополнит недостающий `utm_medium`.
  Для платной рекламы ставьте полные `utm_*`, метка — для своих каналов.
- **Регистр не важен:** `?s=TG` работает так же, как `?s=tg`.
- **Без согласия на аналитику метка не пишется никуда** — как и раньше.

Заодно расширен белый список рекламных параметров: к `yclid` и `gclid`
добавлены `ymclid`, `fbclid` и `erid`. Всё остальное из адресной строки в
аналитику по-прежнему не попадает — проверено тестом на почте и телефоне.

### Что это даст сразу, а что требует сервера

**Сразу, без единой правки на сервере:** канал доезжает до заявки. Атрибуция
подмешивается в поле `page` (`configurator.html`), а админка уже выводит его
строкой `🔗 Источник` в карточке заказа (`assets/js/admin.js`). То есть по
каждому пришедшему заказу будет видно, какой канал его принёс — а это и есть
вопрос «что приносит платящих», а не просто «что приносит сессии».

**Требует проверки на сервере:** сводная таблица источников. Фронтенд кладёт
метку в поле `ref` запроса `POST /visit` в виде `?utm_source=telegram&utm_medium=bot`
(referer, для сравнения, приходит как `https://yandex.ru/search/`). Группировка
`direct_or_unknown / other_referral / yandex / google` живёт на сервере, в этот
репозиторий он не входит, и разбирает ли она `utm_source` — отсюда не видно.
Судя по тому, что в срезе нет ни одной строки с кампанией, размеченных ссылок
до сих пор просто не было. **Это единственное место, где нужно посмотреть
серверный код**: если группировка смотрит только на referer, метки в сводку не
попадут, хотя в карточках заказов будут.

## 2. Подача адресов в IndexNow

Ключ `d485ac6cc21986723e6f627b37da7c5b` и файл-подтверждение лежали в корне с
самого начала, но ни один скрипт их не использовал: сайт публиковался и молча
ждал, пока его обойдёт краулер. Яндекс и Bing поддерживают IndexNow и забирают
страницу по сигналу.

```bash
node scripts/ping-indexnow.mjs            # предпросмотр: что ушло бы
node scripts/ping-indexnow.mjs --submit   # отправить
```

По умолчанию берутся адреса с самой свежей датой `lastmod` в `sitemap.xml` —
то есть ровно то, что изменил последний релиз. Порядок в выпуске:

```bash
node scripts/generate-sitemap.mjs
node scripts/ping-indexnow.mjs --submit
```

Прочие режимы:

| Команда | Что делает |
|---|---|
| `--all` | весь `sitemap.xml` (разумно один раз, после большого обновления) |
| `--since=2026-07-20` | всё, что изменялось начиная с даты |
| `--url=https://akademsalon.ru/guide-normocontrol.html` | точечно, можно повторять |

Без `--submit` скрипт ничего не отправляет — это защита от случайного запуска,
она закреплена тестом. Ответы `200` и `202` означают «принято» (`202` — ключ
ещё проверяется, это нормально при первой отправке). `403` — разошлись
`.indexnow-key` и `<ключ>.txt`; такой рассинхрон ловится до отправки и отдельно
проверяется тестом, потому что в логах релиза он выглядел бы как успех.

## Чего это не делает

IndexNow ускоряет **попадание в индекс**, а не позиции в выдаче. На сегодня
поисковая часть сайта в порядке: 76 индексируемых страниц, ровно столько же в
`sitemap.xml`, заголовки и описания уникальны, `noindex` и `canonical`
расставлены без утечек, у всех 25 гайдов есть Article-разметка. Гайды выложены
в конце июля — ранжирование по ним просто ещё не набралось, и никакой правкой
кода этот срок не сокращается.

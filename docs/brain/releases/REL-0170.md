## Outcome

Academic Salon no longer sends ordinary runtime writes through the shared
SQLite read connection. A dedicated autocommit connection serializes those
writes; the shared reader is query-only, and every reviewed multi-write unit
uses an isolated explicit transaction. The deterministic WAL race that
previously returned `SQLITE_BUSY_SNAPSHOT` now leaves the reader untouched and
completes through the write-only lane without retry or cross-task rollback.

Deposit activation/refund were hardened during review: status re-read and CAS,
money ledger and bonus ledger now form one `BEGIN IMMEDIATE` unit. Concurrent
calls post each economic effect exactly once, and an intermediate failure rolls
the entire unit back.

## Outcome

Analytics v2 no longer looks or behaves like a separate application. It now
projects the same desktop sidebar, mobile appbar, navigation groups, identity,
theme, typography, flat surfaces and responsive geometry as the master's main
cabinet. Analytics remains a separate strict-CSP page and does not load the
write-heavy master controller or the public application runtime.

The complete Russian decision path remains available: compact trust/freshness,
period and source/device/page filters, six summary metrics and trend, current
activity, sources, approximate geography, devices, browsers, operating systems,
entry/exit pages, transitions, strict funnel, events, errors, sessions, safe
session chronology and data-quality health. At 390x844 the first metric is
visible in the initial viewport; tables scroll only inside their wrappers.

Sidebar, mobile search and `Cmd/Ctrl+K` now hand off to the existing Orders
search without moving a query or client data between pages. The one-shot flag is
removed before API access. Runtime auth loss purges rendered analytics, closes
details, cancels late responses and focuses the access gate. Applied filters,
pagination and session detail share one immutable server window.

## Privacy and accuracy boundary

The Analytics v2 backend, schema, collector, consent, retention and revocation
code were not changed in release158. The page still exposes only consented,
anonymous, server-calculated aggregates and safe event attributes. It does not
store or display contacts, order/login IDs, raw IP/user-agent/referrer, query or
form text, files or OAuth data. DB-IP remains a local coarse lookup attribution,
not a third-party runtime request.

Trustworthy history still begins at release157. Legacy rows were not imported,
read or mixed into the dashboard. No production contact, order, log, raw event
or legacy visit row was read or mutated during this release.

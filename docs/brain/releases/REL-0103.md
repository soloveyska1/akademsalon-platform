## Harness recovery evidence

Two earlier switch attempts intentionally ended in automatic rollback:

1. `grep -q` closed a cache-marker pipe after a successful match, producing a
   benign curl write error under `pipefail`;
2. a shell-function-owned SOCKS launcher left its child listening after the
   first 48/48, so the final matrix stopped on an explicit `port_busy` gate.

In both cases the armed trap restored release102, and exact symlinks/hashes were
checked before retry. The marker check was changed to consume the full response;
the tunnel launcher then owned the actual SSH PID and closed it normally. These
were rollout-harness defects, not application failures, and the final complete
run passed without override.

## Result and protected boundaries

The consented request funnel now separates `first_input`, `submit_attempt` and
server-confirmed `submit_success`. `config_step_1` remains a navigation event
but is no longer interpreted as input. The first-input listener stays armed
when a visitor has not consented, so a pre-consent keystroke neither records an
event nor consumes the later measurable first input.

An owner-device exclusion is persisted only after a successful authenticated
`/admin/overview` response. A session-only QA marker uses the same collection
boundary. Both are detected before the shared runtime, so legacy visit hooks
and Yandex Metrika do not start. Strict attribution is silent during that
bootstrap; the exact public URL is restored before Analytics v2 evaluates its
own gates. A later authenticated confirmation or native cross-tab storage event
stops Metrika and revokes first-party anonymous state without changing the
saved consent choice. Persisted deletion proof A is drained before current
identity B, so no older deletion request is overwritten.

The authenticated retention preview remains a protected observation surface.
`/configurator.html?offer_preview=retention` restores the clean URL, stops
vendor analytics and performs no analytics POST or storage mutation even when
an older anonymous identity is seeded. The promo script, promo eligibility,
drafts, price ladder, retention economics, deposit UI and backend deposit
mechanics are unchanged.

All 87 measured public pages load the single-flight configurator guard before
the shared runtime, then strict attribution and Analytics v2. The first ordinary
same-origin configurator activation remains a native link and is measurable
once. Immediate repeats are stopped in window capture before document
telemetry. Busy text is deferred to a microtask so first-click handlers still
see the original target; `aria-busy`, `aria-label`, `pageshow`, modified clicks,
external links, `target` and boolean `download` behavior are bounded.

## Review stops and closure

Independent review rejected earlier candidates until all hard findings closed:

1. owner preview briefly wrote a persistent owner marker — removed;
2. Yandex and strict attribution could start before Analytics v2 — closed by
   the early bootstrap and strict-attribution gate;
3. a repeated mobile tap could reach telemetry twice — closed by window
   capture while preserving the first native activation;
4. owner preview could revoke an older identity — protected preview now skips
   both send and revoke mutation;
5. that change could overwrite a persisted older deletion proof outside
   preview — final ordering drains A before B and has an executable regression.

The frozen result received final GO from the analytics/privacy, mobile UX and
SQLite/release reviewers. No review report is used as proof without the
executable checks below.

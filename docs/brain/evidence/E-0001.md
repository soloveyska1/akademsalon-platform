## Факт

- В production-статике два producer-а `POST /orders`:
  `configurator.html` и guide/knowledge microlead в `assets/js/extras.js`.
- Конфигуратор сохраняет `client_request_id` в `sessionStorage`, повторяет
  неоднозначный POST с тем же ID, не прерывает уже отправленный POST и блокирует
  double-click/Back после подтверждённого success.
- Его текущий success требует HTTP 2xx, `ok:true` и положительный числовой ID
  либо любую непустую строку. Guest-response не обязан содержать явное access
  proof; поэтому malformed string ID и ответ без `claim_url`/guest context должны
  быть отдельными негативными тестами.
- Guide microlead отправляет тот же `POST /orders` без `client_request_id`,
  принимает один `r.ok` без ID и не связывает success с точным делом. Это не
  соответствует `DEC-0006` и `G7`.
- Кабинет читает `/orders` и `/orders/{id}`, использует одноразовый
  `/orders/access/exchange`, обновляется через `/events` и 60-секундный fallback.
  Админка читает `/admin/orders` и `/admin/orders/{id}` через ту же event bus.
- Frontend содержит ручной `/admin/orders/{id}/sync_tg`, но server и Telegram-бот
  не входят в репозиторий. Автоматическая запись operator/bot, реальная
  дедупликация, начальный статус и transaction/outbox boundary не доказаны.
- Полный локальный набор прошёл: 430/430.
- Production API health и публичные features ответили HTTP 200; это доказывает
  доступность чтения, но не delivery заявки.
- UX-review воспроизвёл существующий `UXD-0002` на 390×844: статус и «сейчас ваш
  ход» видны, обязательное действие начинается ниже первого viewport. Наблюдение
  не меняет текущий outcome; после `OUT-001` следующий срез остаётся `OUT-002`.
- Специализированные интеграции Sonnet/Kimi/GLM/Opus/Fable не были доступны.

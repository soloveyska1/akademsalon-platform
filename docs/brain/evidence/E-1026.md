## Problem and bounded intervention

The configurator visibly said that contacts and files were not saved, but the
legacy plan-service draft still wrote `name` and `contact` into localStorage.
Separately, a file-dependent request could be restored on the contact step
after a reload had removed its in-memory attachment. The ordinary Next action
was disabled, but cart checkout and a defensive submit path could still bypass
the missing-material prerequisite.

One page-local checkpoint now makes the existing promise true end to end:

- both legacy draft keys remove any old `fields.name` and `fields.contact`
  residue on the next configurator load;
- autosave keeps the working topic, deadline and requirements, but never writes
  or restores the name, contact or consent;
- every transition to contact, including history restore, cart checkout and
  defensive submit, uses the same material prerequisite;
- if an in-memory file disappeared, the request returns only to Materials and
  visibly explains how to continue by reattaching a file or writing at least
  40 characters;
- the selected work, 14,000–19,500 RUB range, deadline, cart and authorship
  choice are retained.

The intervention changes no CSS, price, discount, offer, backend, admin,
analytics event or submission schema. Contact and consent remain memory-only;
no sessionStorage exception was introduced.

## Privacy, commercial and inference boundary

The change prevents shared-device contact residue and rejects incomplete
high-intent requests before they become ambiguous leads. It preserves the
visitor's chosen scope and price instead of silently restarting or downgrading
the quote. This protects trust and reduces manual re-qualification, but it does
not prove conversion or revenue uplift. The release proof below closes
publication, production smoke and rollback without submitting a form.

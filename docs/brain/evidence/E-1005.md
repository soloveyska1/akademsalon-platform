## Implemented contract

- `paymentContextFor()` distinguishes `unknown`, `none`, `preparing`, `due`,
  `checking` and `transfer`. Positive due becomes an action only when both amount
  and authoritative `claimed=false` are present; absent evidence fails closed.
- `caseContextFor()` is the shared source for priority, overview, bands, payment
  workspace, ledger, destinations and live-list signature. Action precedence is
  `payment > price > review > files > message`; pause and terminal states own the
  surface and suppress client mutations.
- `nowCard()` uses one list snapshot rather than mixing summary with a different
  open detail. Context-only list changes repaint home once while stable element
  IDs/data keys restore focus, drafts and scroll.
- `paymentActionAllowed()` rechecks the current detail/id immediately before all
  three payment paths: online, deposit and `paid` transfer mark. `checking`,
  paused, unknown, terminal or mismatched detail cannot reach an API mutation.
- Client pause routes to Terms when self-unpause exists; master pause routes to
  chat. Payment/ready bands remain silent and unpause appears once.
- The changed JS and CSS have independent `context=truth1` cache keys. Dark base
  CTA is `#fffaf3` on `#c63e28`, 4.91:1; the browser pointer-hover state observed

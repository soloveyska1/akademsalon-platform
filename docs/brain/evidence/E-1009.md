## Reproduced failures

The shared global-search markup is emitted by `assets/js/polish15-chrome.js`,
but the complete redesigned presentation is concentrated in the home-only
`assets/css/home-story.css` instead of the shared chrome layer. Runtime confirms
the consequence rather than inferring it from source:

- `/services.html`, 1440×1000 light: the input collapses to about 46×52 px,
  brand text wraps into a narrow stack, and close/shortcut presentation is not
  usable as a desktop search sheet;
- `/dashboard.html`, 390×844 dark with empty demo state: the focused input is
  about 44×48 px and does not visibly expose a normal query line;
- `/`, 390×844 light with `курсовая по психологии`: the home layer is present,
  but a late mobile rule restores a three-column result row, leaving the title
  about 94 px wide; the third suggestion chip clips without an affordance;
- `/services.html`, 360×800: the local catalogue controls overlap the fixed dock
  by 44 px; at 390×844 the measured overlap remains 8.7 px;
- the sticky catalogue toolbar uses `top:0` at a layer below the fixed 70 px
  header. A center-point hit test can therefore resolve to header chrome instead
  of the intended catalogue control.

These are P1 reachability/presentation failures. Dialog/listbox semantics,
arrow navigation, Escape and focus return were reproduced green; they remain
regression guards rather than rewrite targets.

## Findability baseline

- Query `экономика` matches two discipline pages, but unrelated Commission
  content precedes them; on mobile the first relevant route is materially below
  the initial result area.
- Query `дипломная` returns zero despite existing ВКР/diploma inventory.
- A visible `Найдено: 1` is present for at least the working query `курсовая по
  психологии`. The defect is therefore not “no counter exists”; it is absence of
  one stable visible/`aria-live` result-count contract across positive and zero
  states.
- Default services combines situation, stage, work type and discipline as four
  competing navigation models. Cards are about 330–390 px high with 11–12 px
  supporting text. This is evidence for a post-fix IA hypothesis, not authority
  to change the protected inventory now.

The existing OUT-005 contract suites stayed green: 55/55 focused checks, 12 hub
cards, 9 disciplines, 22 detail URLs and the route/price/schema inventory.
Independent catalogue audit also reproduced one-primary behavior, no horizontal
overflow and the saved-intent handoff. Any implementation must preserve the
12/9/22 inventory, ItemList 13, exact routes/prices/schema/canonical/no-JS, saved
intent, AA contrast and 44 px targets.

## Frozen decision boundary

Bugfix scope is limited to geometry/reachability, shared global-search
presentation parity, query-side aliases, obvious deterministic ranking, stable
visible/`aria-live` count and explicit zero state. Global search is navigation
between product routes; services-local controls are facets within the current
inventory. Only one text input may be visible on the services surface.

Default catalogue IA remains unchanged through those gates. Open a separate
prototype only if, after the fixes, a representative user still needs more than
15 seconds or more than two wrong navigation moves to reach a typical route,
cannot say where to start, or visibly alternates between at least two navigation
models. If opened, the first and only architecture hypothesis is `тип работы`
as the leading axis with situation/stage/discipline as secondary facets; it must
reuse the protected inventory and saved intent.

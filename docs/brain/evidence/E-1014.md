# E-1014 — mobile-first и PWA: измеренная база до переделки

- Date: 2026-08-06, Europe/Moscow.
- source_type: deterministic-local (WebKit device profile) + real-device
  screenshot (iOS Simulator) + static source measurement.
- Canonical base: `ece385da72ded618b6a83374abff035fbd637f9f`.
- Branch: `claude/mobile-first-audit`.
- Workstream: `WS-9279a4aa7fe8498bb97b284f916f188c`.
- Outcome: `OUT-008`.
- Mutations: нет. Аудит только читает продукт; продуктовый код не изменялся.

## Как измерялось

- Реальный движок WebKit (Playwright 1.62), профиль телефона 390×844,
  `deviceScaleFactor=3`, `isMobile`, `hasTouch`, iOS user agent. Все 92 страницы
  из корня репозитория, отдаваемые локальным статическим сервером.
- Контрольный прогон тех же страниц на 1440×900, чтобы отделить «телефон не
  показывает» от «этого нет вообще».
- Реальный iPhone 17 Pro (iOS 26.4, симулятор) — снимки экрана через
  `xcrun simctl io booted screenshot` для проверки настоящего рендера.
- Статический замер CSS/JS: подсчёт медиазапросов, `display:none`, `font-size`,
  `env(safe-area-inset-*)`, `dvh/svh`, вес ассетов в сыром виде и под gzip -6.

Ограничение: живая панель симулятора и жесты через MCP-интеграцию недоступны —
инструмент сообщает «Xcode is installed but not selected», хотя
`xcode-select -p` уже указывает на `/Applications/Xcode.app/Contents/Developer`,
а `xcodebuild -version` отвечает `Xcode 26.4`. Поэтому тапы, ввод с реальной
клавиатуры и проверка жестов на устройстве не выполнялись; клавиатура измерена
эмуляцией сжатия области просмотра, что помечено отдельно.

## Что уже сделано хорошо (не ломать при переделке)

- Все 92 страницы несут `width=device-width, initial-scale=1.0,
  viewport-fit=cover`. Ни одной страницы без viewport meta.
- 293 обращения к `env(safe-area-inset-*)`: bottom 110, left 86, top 53,
  right 44. Док и шапка считают вырез и домашний индикатор.
- 87 использований современных единиц высоты (`100dvh` 54, `100svh` 33) против
  всего 6 устаревших `100vh`.
- Горизонтальных протечек нет: на всех 92 страницах `scrollWidth - innerWidth`
  равен 0 при 390 px.
- Поля ввода почти везде ≥16 px, поэтому iOS не зумит форму при фокусе.
  Исключение — две области в `admin-covers.html` (`textarea#ttl` 12 px).
- Ландшафт 844×390 не даёт протечки.

## Измеренные дефекты

### 1. Архитектура остаётся вычитанием из десктопа

- 753 объявления `max-width` против 269 `min-width` по всем CSS (2.8 : 1).
- Внутри `max-width` медиазапросов: **316 правил `display:none`** и
  **855 переопределений `font-size`**. Это в 7 раз больше, чем видно по одному
  `assets/css/mobile.css` (43 и 104), — «ужимание» размазано по 12+ файлам,
  крупнейшие: `home-release.min.css` (78 скрытий), `mobile.css` (43),
  `chrome.css` (35), `polish15-account.css` (30), `polish15-chrome.css` (25).
- Следствие в цифрах: из 7085 текстовых блоков, видимых на 1440 px, на телефоне
  не показаны 759 (10.7%). Доля потерянного максимальна на `configurator.html`
  и `start.html` (33%), `knowledge.html` (28%), `vedenie.html` (23.5%).

### 2. Первый визит с телефона остаётся без нижней навигации

- Док `.mobile-cta.mnav.mobile-dock` строится в `assets/js/app.js:2786` и по
  замыслу комментария там же должен быть «на всех страницах».
- Фактически при первом заходе он имеет `visibility:hidden` и стоит на
  `rect=0,844,390,74`, то есть ровно под нижней кромкой экрана: правила
  `:root.has-consent-bar` в `assets/css/mobile.css:2042+` прячут его, пока висит
  баннер согласия.
- Баннер согласия — это `div#lrail`, `position:fixed`, `rect=10,634,370,200`,
  `z-index:96`. Он занимает нижние 200 px экрана на 87 страницах из 92.
- После сохранения согласия док появляется: `rect=0,770,390,74`, кнопки
  73×54 px, основная 73×70 px, `body` получает `padding-bottom:90px`.
- Итог: пока пользователь не ответил на баннер, нижние 200 px каждого экрана
  занимает юридический блок, а навигации приложения нет вовсе.

### 3. Ключевые экраны остаются без оболочки

- `configurator.html` и `start.html`: дока нет в DOM вообще (`no-mcta`),
  `.mobile-appbar` в `display:none`. У конфигуратора есть собственная нижняя
  панель шага, но выхода в остальной сайт с экрана нет.
- `dashboard.html` (кабинет): док присутствует в DOM, но `display:none`;
  `padding-bottom` у `body` равен 0. Кабинет — единственный раздел с
  постоянной работой — лишён нижней навигации.
- `.mobile-appbar` отсутствует на 4 страницах: `admin.html`,
  `configurator.html`, `oplaceno.html`, `start.html`.

### 4. Тач-цели и плотность

- Из 3153 интерактивных элементов на 92 страницах **297 (9.4%) меньше 44×44 px**;
  хотя бы одна такая цель есть на **76 страницах из 92**.
- Худшие: `admin-covers.html` 18 из 31, `requisites.html` 15 из 58,
  `komissiya-0.html` 13 из 51, `about.html` 7 из 27, `plus.html` 7 из 35,
  `referral.html` 7 из 30.
- 936 пар соседних целей с просветом меньше 8 px на 90 страницах.
- 4090 элементов с кеглем меньше 14 px на 91 странице.

### 6. Длина страниц

Медиана высоты страницы на телефоне — 7.0 экранов. Рекорды: `oferta.html`
26208 px (31.1 экрана), `privacy.html` 19170 px (22.7), `loyalty.html`
18028 px (21.4), `guide-zashchita-diploma.html` 11993 px (14.2).

### 7. Клавиатура (эмуляция, требует подтверждения на устройстве)

При сжатии области просмотра до 390×508 (клавиатура iOS ≈336 pt) на
`priyomnaya.html` сфокусированное поле `textarea#supportQuestion` занимает
325..499, а фиксированный баннер согласия `lrail` — 298..498. То есть поле,
в которое пользователь печатает, перекрыто юридическим блоком. Проверку на
живом устройстве нужно повторить после восстановления интеграции с симулятором.

### 8. PWA отсутствует полностью

- `manifest.json` / `.webmanifest`: файла нет; `rel="manifest"` — 0 вхождений
  во всех 92 HTML.
- Service worker: файла нет; `serviceWorker` в `assets/js/*.js` — 0 вхождений.
  Офлайн-ответа нет.
- `apple-mobile-web-app-capable` и `apple-mobile-web-app-status-bar-style` —
  0 вхождений.
- Есть только частичная база: `apple-touch-icon` (168 вхождений),
  `theme-color` (93), файлы `assets/img/apple-touch-icon.png`,
  `favicon-32.png`, `favicon-120.png`, `favicon.svg`, `logo-mark.svg`.

## Ложные срабатывания, проверенные и отклонённые

- «Дока нет ни на одной странице»: артефакт харнесса — селектор обрезался до
  двух классов. Перемер по полному селектору показал, что док есть и работает
  после согласия.
- «`price.html` рендерится на 980 px без viewport meta»: такой страницы не
  существует, страница цен называется `tariffs.html`. Замер был получен на
  ответе 404.
- «JS-ошибка на 90 страницах»: `Fetch API cannot load
  https://akademsalon.ru/api/auth/session` — следствие локального origin,
  а не дефект продукта.
- «Поле уходит за пределы экрана при клавиатуре на `gift.html`»: артефакт
  эмуляции, браузер сам доскроллит поле в видимую область.

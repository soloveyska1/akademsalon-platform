# E-1017 — изоляция 502 по виртуальным хостам

- Date: 2026-08-21, Europe/Moscow.
- source_type: live read-only diagnosis + deterministic local contract + bounded
  production Nginx/watcher hotfix + executed rollback/forward drill.
- Canonical base: `d7817620839c7e3d2f4fce777cfda96f5d5bde64`.
- Implementation: `0dcab81b6f414928aa76e3bf083e0c6ababaf401`.
- Workstream: `WS-1065aa22f3ed462bbb2cbe23b05459e3`.
- Outcome: `OUT-006`; release gate: `G10`.

## Причина, а не симптом

Уведомление показало 91 ответа `502` на PHP/WordPress probes. В момент аудита
`akademsalon.ru`, `/api/health` и `salon-bot-v2.service` были здоровы; те же три
пути на основном домене уже отвечали штатным `404`.

Обезличенная агрегация Nginx error log локализовала поток: 540 соединений шли к
`kiskispace.duckdns.org`, ещё 5 — к legacy sslip host, и ни одно — к
`akademsalon.ru`. Оба старых host проксировали в отсутствующий
`127.0.0.1:4310`; PM2-процесс Duo Space имел status `stopped`, а listener/service
на 4310 отсутствовал. Канонический API Салона слушал свой `127.0.0.1:8090`.

`/root/salon_watch/watch.py` читал общий `/var/log/nginx/access.log` всех доменов
VPS. Поэтому отказ соседнего virtual host ошибочно назывался «серверными
ошибками у посетителей» Салона. Дополнительно исполняемая backup-копия
`api.pre-manifest-20260806T141221Z` оставалась в `sites-enabled` и создавала
шесть предупреждений duplicate `server_name` при каждом `nginx -t`.

## Исправленный контракт

- TLS server `akademsalon.ru` пишет отдельный
  `/var/log/nginx/akademsalon-watch.log` в существующем формате `noqs`, без IP,
  user-agent, referrer и query string; watcher читает только этот файл.
- Статический Салон локально возвращает `404` для любого `.php` path до выбора
  upstream. Явный `/api/` proxy не изменён.
- Остановленный Kiskispace сохраняет hostname/TLS, но возвращает локальный
  `404` вместо proxy в отсутствующий 4310. Возобновление личного приложения
  требует отдельного решения; hotfix не публикует его данные.
- Backup-конфиг перенесён из `sites-enabled` в root-only incident backup. Nginx
  больше не исполняет его как второй site.
- Ложный суточный `day.5xx=521` сброшен в `0`, а старый 30-минутный throttle
  удалён под штатным file lock. Поэтому новый настоящий 5xx Салона снова
  поднимет сигнал сразу. Исходный state сохранён отдельно.

Backend, SQLite, static release, Analytics v2 schema/rows, заказы и формы не
изменялись; production submit не выполнялся. Client IP/UA не выводились и не
попали в evidence.

## Reproduced privacy/reliability P1

1. Same-origin `/api/visit` fetch has no `credentials:'omit'`. Browser Fetch
   defaults may attach the cabinet session cookie. `dashboard.html` is excluded
   from Metrika but not from the internal visit beacon. Server-side linkage is
   unknown; client-side isolation is not fail-closed.
2. Visit and Metrika page identity use raw `location.pathname`. An arbitrary
   Nginx 404 path containing an email/token-like string can therefore enter
   analytics despite the documented cleaned-page contract. Attribution already
   contains an allowlist-plus-`/other` pattern that can be reused.
3. Reject/revoke deletes `salon_vid` but leaves `salon_attr_v2`, including entry,
   source and first/last timestamps. Regrant can resurrect old first-touch data;
   expiry does not supply a complete attribution purge.

These are blockers to expanding analytics, not a claim of observed server data
linkage. Exact failure-first tests must reproduce each client behavior without a
production call before implementation.

## Privacy foundation result

Implementation commit `1011060c9b2f30b55809ab9bb253ae64cf811925`
closes the reproduced client-side isolation failures without adding a new
measurement milestone or changing visible UI:

- `/api/visit` is HTTPS/canonical-host only, uses `credentials:'omit'`, sends
  one best-effort request with no retry and is silent on dashboard, admin,
  payment-link, impersonation and desktop-preview contours;
- page identity is an exact inventory of the 92 root documents with `/other`
  fallback; persisted legacy `entry` and `lastEntry` are canonicalized before
  reuse;
- reject, revoke and expiry remove consent-linked browser ID, attribution and
  `_ym*` state; a document opened without consent cannot capture its UTM or
  referrer after a same-document regrant;
- legacy marks and semantic events use finite names and dimensions. Unknown,
  contact-like and token-like input is dropped rather than sanitized into a
  new identifier. The legacy home route matrix has 336/336 unique compact
  mappings and zero truncation collisions;
- `/qa` no longer combines question contact data with `salon_vid`; all 89
  direct app consumers, the home bundle and five supporting-runtime consumers
  carry one atomic privacy cache wave.

The failure-first contract moved from 1/5 at commit `23318be` to 10/10.
Independent final review is P0=0/P1=0/P2=0 and ran 59/59 focused checks. Final
local proof on the implementation commit: product 492/492, Brain 39/39, strict
Brain validation, JS syntax, reproducible home bundle and `git diff --check`.
A clean WebKit smoke at 390 and 1024 had no overflow or console error, made zero

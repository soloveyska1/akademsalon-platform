# Изоляция production-мониторинга

Этот контур не считает общий `/var/log/nginx/access.log` источником истины для
Академического Салона. На общем VPS такой файл смешивает разные домены, поэтому
ошибка остановленного соседнего приложения может быть ошибочно подписана как
сбой посетителя `akademsalon.ru`.

## Контракт

- Канонический TLS-хост `akademsalon.ru` пишет отдельный privacy-safe лог
  `/var/log/nginx/akademsalon-watch.log` в формате `noqs`.
- Формат не содержит IP, user-agent, referrer или query string. Дозор читает
  только этот файл; глобальный лог остаётся операционным и не участвует в его
  счётчиках и уведомлениях.
- Публичная часть Салона статична. Любой путь с `.php` получает локальный `404`
  до выбора upstream; настоящие API-маршруты остаются в явном `/api/` location.
- Неактивный виртуальный хост на общем VPS не проксируется в отсутствующий
  процесс. Пока владелец отдельно не возобновил приложение, такой хост отвечает
  локальным `404`, сохраняя TLS и не создавая поток `502`.
- Резервные копии конфигурации не лежат в `sites-enabled`: wildcard Nginx
  исполняет любой файл в этом каталоге и иначе создаёт дубли `server_name`.

## Выпуск

1. Снять SHA-256 активного Nginx site, неактивного vhost и watcher; убедиться,
   что нужный upstream действительно не слушает и не имеет active service.
2. Скопировать точные исходные файлы в отдельный root-only backup-каталог.
3. Добавить директивы из `nginx-salon-watch.conf` в основной TLS server, сменить
   источник watcher на выделенный лог и заменить proxy неактивного vhost на
   локальный `404`.
4. Убрать исполняемую backup-копию из `sites-enabled`, не удаляя её из backup.
5. Выполнить `python3 -m py_compile`, `nginx -t`, reload Nginx и один обычный
   цикл watcher. Backend, база и статический release не перезапускаются.
6. Проверить с VPS и внешней сети: `/` и `/api/health` равны `200`, случайный
   путь и PHP/WordPress probes равны `404`, сервисы active, новый лог не содержит
   чувствительных полей.

## Rollback

Rollback восстанавливает точные байты трёх изменённых файлов и прежнюю
backup-копию в `sites-enabled`, затем повторяет `python3 -m py_compile`,
`nginx -t`, reload и тот же GET-only smoke. База, заказы, аналитические raw rows,
контакты и клиентские материалы в этом процессе не читаются и не меняются.

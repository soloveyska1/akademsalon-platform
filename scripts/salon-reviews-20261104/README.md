# Два новых отзыва (ноябрь 2026)

04.11.2026, владелец прислал два скриншота переписки из Telegram с просьбой «Закинь в отзывы».

## Что сделано

- `prepare_reviews.py <папка со скриншотами> <out>` — как в `salon-reviews-20261030`: аватарки
  в реакциях запикселены (58), ответ мастера «Крутяк)» с аватаркой под сообщением клиента срезан и фамилия преподавателя
  запикселена (59),
  по пикселю рамки окна с краёв. Полный WebP и миниатюра шириной 420 px. Исходные PNG в репозиторий
  не кладём: на них аватарки без пикселизации.
- `img/` — готовые `review-58.webp`, `review-59.webp` и `thumbs/` (на сайте — `assets/img/reviews/`).
- `add_reviews.py <папка с HTML релиза> <img>` ставит две карточки первыми на `reviews.html`
  (разметка `rv-card`) и меняет на главной «54 сообщения» / «54 отзыва» на «56 сообщений» /
  «56 отзывов». В исходнике главной (`scripts/salon-home-v4-20261030/main.html`) число поправлено так же.

| № | тема | подпись |
|---|---|---|
| 59 | после сдачи | «Защита прошла отлично, ничего не спросили, похвалили авторскую анкету» |
| 58 | о работе вместе | «Всё было на высоте! Выручаешь как всегда» |

## Релиз — одной командой на сервере

Облачная сессия не достаёт до сервера и до akademsalon.ru, поэтому финальный шаг запускает владелец
на сервере под root:

```bash
curl -fsSL https://raw.githubusercontent.com/soloveyska1/akademsalon-platform/claude/hopeful-archimedes-rpxypc/scripts/salon-reviews-20261104/release.sh -o /root/release-reviews-56.sh && bash /root/release-reviews-56.sh
```

`release.sh` повторяет порядок прошлых релизов:

1. берёт живой `current` (`readlink -f`); если `review-58` уже на сайте — выходит, ничего не трогая;
2. скачивает `add_reviews.py` и четыре картинки с GitHub и сверяет каждый файл по SHA-256;
3. собирает `release<N+1>-reviews-56-<дата>` копией `current` (`cp -a`), кладёт картинки
   в `assets/img/reviews/` и `thumbs/` с владельцем каталога, запускает `add_reviews.py`;
4. проверяет: карточек было 54, стало 56, первыми 59 и 58, на главной «56 сообщений» и ссылка
   «56 отзывов», изменилось не больше 7 файлов (`reviews.html`, `index.html`, `home-v4.html`, 4 картинки);
5. ещё раз сверяет, что `current` не сменился, и атомарно переключает симлинк;
6. smoke по живому домену: 56 карточек, «56 отзывов» на главной, картинки `200 image/webp`.
   Если smoke не прошёл — сам откатывает `current` на прежний релиз.

В конце печатает команду отката. `--dry-run` только собирает и проверяет релиз, не переключая сайт.
Pillow на сервере не нужен: без него `add_reviews.py` берёт размеры миниатюр из `THUMB_SIZES`
(разметка байт в байт как с Pillow).

Проверено в облаке на имитации сервера (`releases/`, симлинк `current`, локальные HTTP-серверы
вместо GitHub и домена; главная — `main.html` до правки 54 → 56): пробный прогон, боевой прогон
54 → 56 с переключением, автооткат при провале smoke, повторный запуск («уже на сайте»).
На настоящем сервере не запускалось.
